# **"获取所有课程"接口压力测试报告**

## 1. 报告摘要

| 项目 | 内容 |
| :--- | :--- |
| **测试接口** | `[HTTPS]` 获取所有课程列表 |
| **测试目标** | 评估接口在低并发场景下的性能表现与稳定性 |
| **测试结论** | **通过** ✅。接口在10并发用户场景下，**性能表现优异**，响应速度极快，无任何错误，满足预期性能要求。 |
| **发现风险** | 存在一个响应时间异常值（432ms），建议监控但暂不影响本次结论。 |

## 2. 测试环境与配置

| 类别 | 配置/说明 |
| :--- | :--- |
| **测试工具** | Apache JMeter |
| **测试环境** | 预生产环境 / 测试环境 (需明确) |
| **服务器配置** | (例如：2核4G Linux) |
| **网络环境** | 内网 / 局域网 (理想低延迟环境) |
| **数据背景** | **课程数据量：约10条** |

## 3. 测试场景与目标

* **场景描述**：模拟10个用户逐步启动（每秒启动1个用户），每个用户循环执行100次“获取所有课程”的请求。
* **性能目标**：
    1. 接口平均响应时间 < 100ms
    2. 接口错误率 = 0%
    3. 探索系统在该场景下的基本吞吐能力。

## 4. 测试执行结果

### 4.1 关键性能数据

| 性能指标 | 测试结果 | 目标 | 是否达标 |
| :--- | :--- | :--- | :--- |
| **总请求数** | 1000 | - | - |
| **平均响应时间** | **7 ms** | < 100 ms | **✅ 是** |

| **吞吐量 (TPS)** | **107.6** | - | - |
| **接收流量** | 216.5 KB/s | - | - |

### 4.2 性能指标

说明：绝大多数请求响应时间集中在较低水平（26ms以内），最大响应时间存在一个明显异常点。

## 5. 详细分析与结论

### 5.1 结果分析

1. **响应时间 (极佳)**
    * 平均响应时间仅为 **7ms**，90%的请求在 **14ms** 内返回，表现出**极快的速度和极高的稳定性**
      。这得益于课程数据量很小（10条左右），服务器处理和网络传输耗时极短。
    * 存在一个 **432ms** 的异常最大响应时间。这在压力测试中常见，通常由**后端服务器GC（垃圾回收）、网络微小抖动或数据库连接波动
      **等因素引起。鉴于其仅出现一次且错误率为0，可初步判断为偶然现象，风险较低。

2. **吞吐量 (良好)**
    * 系统吞吐量为 **107.6 TPS**，即每秒可处理该接口请求107.6次。对于10个并发用户的场景，此吞吐量表现良好。

3. **正确性与稳定性 (完美)**
    * **错误率为 0%**，表明所有1000次请求均成功返回。接口在测试过程中**完全稳定**。

### 5.2 结论

本次测试中，**“获取所有课程”接口在10并发用户、1000次请求的压力下，性能表现完全达到并远超预期目标。**
接口响应迅猛，服务稳定无错误，可以轻松应对该级别的并发请求。

## 6. 建议与后续计划

1. **监控建议**：在生产环境中对该接口的响应时间（尤其是P99分位值）进行持续监控，确认432ms的异常值是否会在高并发时段频繁出现。
2. **后续测试建议**：
    * **增加并发量**：建议下一步将线程数逐步增加至50、100，以探测系统的性能拐点和最大承载能力。
    * **全面场景测试**：本测试仅针对一个接口。建议对系统其他核心接口（如：登录、查询大量数据的接口、写入接口）进行压力测试，以全面评估系统性能。
    * **压力下监控**：在后续高压测试中，务必同步监控服务器（CPU、内存、IO）和数据库（CPU、慢查询、连接数）指标，便于快速定位瓶颈。
